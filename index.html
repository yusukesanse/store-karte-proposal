店舗カルテシステム
システム案DRAFT

多店舗 耐震・リニューアル計画のために整備した「店舗カルテ雛形 v1.0」と「調査要領書 v1.0」を、Excel と共有フォルダの運用から、全店舗を横断して入力・集計・判定できる Web アプリへ移すための構成案です。項目や評価の物差しは雛形のまま引き継ぎ、アプリは「入力を楽に、集計を自動に、記録を残す」役割に徹します。

対象 全30店舗 調査項目 12区分・168項目 評価 20軸・100点満点 投資区分 S／A／B／C 調査期間の標準モデル 約6ヶ月

00この資料について

本資料は「何を作るか」（構成・機能・画面・データ・運用）を共有するためのシステム案です。費用・体制・契約条件は別紙のお見積りで提示します。ここに書いた内容は打ち合わせでの確認を経て確定させる前提のドラフトで、章末の「ご確認したい事項」への回答によって一部が変わります。

前提資料調査要領書 v1.0＋別紙1〜4

5フェーズの調査手順、体制、依頼資料20点、現地調査・ヒアリングの様式

01目的と現状の課題

調査の目的は雛形に定義されているとおり、全店舗を同じ物差しで「建物・施設・商圏・資産」の4視点から診断し、投資区分（S 戦略投資／A 継続投資／B 維持投資／C 再編検討）と優先順位を決める材料を作ることです。システムはこの目的に対する道具であり、目的そのものを変えません。

いまの設計（Excel＋共有フォルダ）で起こること

雛形と要領書は完成度が高く、そのまま調査を始められます。一方で、30店舗・約6ヶ月・複数の入力者という規模になると、Excel 運用では次の作業が人手に残ります。

場面Excel運用で起こること影響
全店比較各カルテの「スコアリング」結果をサマリー一覧へ手で転記する転記ミス・転記漏れ。カルテを直すたびに一覧も直す
相対評価C1「現在商圏規模」などは全店データが揃ってから分布を見て基準を確定し再採点する再採点のたびに30ファイルを開き直す
版管理パイロット後に雛形を v1.1 へ改訂すると、着手済みのファイルにも反映が要る店舗ごとに版がずれる。どの版で採点したか追えなくなる
同時作業調査スタッフ・設計担当・商圏分析担当・クライアント側担当が同じファイルを順番に触る待ち時間、上書き、最新版の取り違え
写真・資料写真は共有フォルダ、カルテには写真番号を手で書いて紐付ける紐付けが切れる。現地で撮った写真の整理が翌日に持ち越す
進捗・品質進捗率はカルテ内で自動計算されるが、30店舗の進捗を横断して見る場所がない。レビュー（記入者→設計担当→PM）の状態も追えない週次定例で各ファイルを開いて確認
年次更新翌年以降の更新はファイルのコピーで世代を増やす前年との差分が取れない。ファイルが増殖する
守秘ファイルの配布で共有するため、再編に関わる所見も同じファイルに載る閲覧範囲をファイル単位でしか切れない

システムで目指す状態

「調査で使う道具」と「判定後も使い続ける台帳」を、ひとつのアプリにします。

01雛形をそのまま写す

項目・選択肢・評価基準・重み・判定ロジックはマスタとして持ち、版番号で管理する。画面上の並びも雛形と同じ 1-1 → 4-2 の順にする

02現場優先の入力

1項目1行、調査状況をその場で更新、写真はその項目に直接添付。調査日・記入者は自動記録。タブレット・スマートフォンでも入力できる

03全店を横断して見る

サマリー一覧・分布・相対評価は自動集計。進捗とレビュー状態を全店で一覧できる。判定会議資料と Excel／PDF の出力を用意する

02システムの全体像

利用者はブラウザから1つのアプリにログインし、権限に応じた店舗・区分を入力または閲覧します。データはすべて1つのデータベースに入り、集計・判定・出力はそこから作られます。

特徴は3つです。①入り口が1つ（ファイルの受け渡しがない）、②データが1箇所（転記がない）、③出力は雛形と同じ体裁（判定会議や社内説明でこれまでの様式をそのまま使える）。

03主要機能

雛形・要領書のどの部分をアプリのどの機能が受け持つかを対応させて並べます。右列が「Excel版ではどこにあったか」です。

  • F-01

    全店舗ダッシュボード

    30店舗のスコア（A〜D・総合）、耐震フラグ、自動判定、PM最終判定、優先順位、実施フェーズ、進捗率を一覧。並べ替え・絞り込み（ブロック、耐震区分、判定）。分布（総合スコアのヒストグラム、A×C の判定マトリクス上の散布）を表示。

    全店舗サマリー一覧_v1.0.xlsx手転記だった一覧を自動集計に
  • F-02

    店舗カルテ（表紙）

    調査基本情報、物件概要（1-1・1-2から自動表示）、スコアサマリー、耐震アラート、12シートの進捗、総評。店舗ごとの入口画面。

    雛形「表紙」シート
  • F-03

    調査入力（12区分・168項目）

    1項目1行で「記入内容・単位／形式・特記事項・情報源・調査方法・調査状況」を入力。選択式はマスタのドロップダウン。自動計算項目（築年数・残存契約期間・人口指数・トヨタ保有シェア）は入力不可で自動表示。調査日・記入者は自動記録。フェーズ／担当／調査状況で絞り込める（別紙1の使い方をそのまま画面に）。

    雛形 1-1〜4-2 シート＋別紙1黄セル・灰セルの区別を画面上の入力可否に
  • F-04

    写真・受領資料の添付

    写真を項目に直接添付（スマートフォンのカメラから可）。写真番号は自動採番、店舗・区分・項目で検索。受領資料（別紙2の20点）は店舗ごとに受領状況・受領日・ファイルを管理し、「優先度A未受領」を一覧できる。

    共有フォルダ 02_受領資料／04_写真＋別紙2手書きの写真番号紐付けを不要に
  • F-05

    ヒアリング記録

    別紙4の質問票（店舗責任者／営業／サービス）をフォーム化。回答は生データとして保存し、カルテ 2-3-08〜10 に要点を転記する欄を別に持つ。匿名化フラグで、個人が特定される記述を閲覧制限できる。

    別紙4 ヒアリング質問票
  • F-06

    スコアリング・投資区分判定

    20軸を1〜5点で入力（評価基準の文言を横に表示）。重み（既定 30／20／30／20、合計100）を調整可。換算点・総合スコア・耐震フラグ・自動判定（A×C マトリクス）を自動計算し、PM最終判定と判定理由を記録。相対評価軸（C1 現在商圏規模など）は全店の分布から自動で基準を算出し、再採点が要る店舗を知らせる。

    雛形「スコアリング」「評価基準」シート相対評価の再採点を自動化
  • F-07

    レビュー・承認

    店舗×シートごとに「記入中 → セルフチェック済 → 設計担当レビュー済 → PM承認」の状態を持つ。1-2・4-2 は設計担当レビューを必須にする。誰がいつ何を変えたかの変更履歴を項目単位で残す。

    要領書 7章 品質管理ルール
  • F-08

    マスタ・版管理

    調査項目・選択肢・評価基準・重み・判定ロジックを版付きで管理。パイロット後の v1.1 改訂を全店へ一括適用し、各店舗が「どの版で採点したか」を保持する。編集は PM 権限のみ。

    雛形「選択肢マスタ」＋要領書 11章 版管理
  • F-09

    出力

    店舗カルテ（PDF、および雛形と同じ列構成の Excel）、全店舗サマリー一覧（Excel）、ブロック別の判定会議資料（PDF）。要領書のフォルダ構成（03_カルテ／06_スコアリング・判定 など）に沿ったファイル名で書き出す。

    要領書 8章 格納ルール既存の様式・命名を維持
  • F-10

    年次更新（調査年度の世代管理）

    調査年度を切り替えて同じ店舗の回答・スコアを世代管理。新年度は前年の値を引き継いだうえで「更新が必要な項目」だけを対象に依頼できる。前年との差分表示。

    （新規）年次・定期更新の運用を最初から組み込む
  • F-11

    利用者・権限・監査ログ

    役割ごとに閲覧・入力できる店舗と区分を制御（06章）。ログイン・閲覧・変更の記録。退職・異動時のアカウント停止。

    要領書 9章 守秘

作らないもの（今回のスコープ外として明示）：GIS の商圏計算そのもの（jSTAT MAP 等の外部ツールの結果を入力・添付する）、耐震診断・不動産鑑定の計算、会計システムとの連携。外部データの取り込み（クライアント実績データ・UIO データの CSV 取込）はオプションとして 12章で確認します。

05データ構造

データは「店舗 × 調査年度」を軸に、雛形の項目マスタへの回答として持ちます。項目そのものはマスタなので、雛形の改訂（v1.1）はマスタの版を上げるだけで済み、過去の回答は当時の版に紐付いたまま残ります。

07調査フェーズとの対応

要領書の5フェーズはそのまま。各フェーズでアプリが受け持つことを対応させます。

フェーズ要領書での内容アプリが受け持つこと

08技術構成

弊社が他案件で本番運用している構成を採ります。特殊な部品を使わず、保守と引き継ぎがしやすいこと、月額の固定費が読めることを優先しています。

アプリNext.js ＋ TypeScript

画面と業務ロジック。型で 168 項目・20 軸の定義を固定し、マスタとの食い違いをビルド時に検出する

データSupabase（PostgreSQL）

店舗・年度・回答・スコアを関係データベースで管理。権限は行単位（店舗×区分）でデータベース側にも掛け、画面の実装漏れで漏れない構造にする

ファイルSupabase Storage

写真・受領資料は項目・店舗に紐付けて保管。アクセスは同じ権限で制御

認証メール＋パスワード（招待制）

管理者が招待した人だけがログインできる。多要素認証は管理者・PM に推奨。認証・権限の設計は着手前に貴社と確認のうえ確定します

ホスティングVercel

変更を安全に反映できる仕組み（プレビュー → 本番）。利用者数の増減に手作業なく追従

出力PDF／Excel 生成

雛形と同じ列構成の Excel、判定会議用 PDF。既存の様式・フォルダ命名に合わせる

この構成を選ぶ理由

  • 実績：弊社が本番運用中の Web アプリと同じ構成で、引き継ぎ資料・運用手順の雛形がある
  • 保守のしやすさ：サーバー OS やミドルウェアの面倒を見る作業がなく、保守の中身を「アプリの改善」に寄せられる
  • 費用の見通し：クラウド利用料は利用規模に応じた月額で、30店舗・数十名の利用では小さい
  • 持ち出せる：データは標準的な PostgreSQL と通常のファイルなので、契約終了時に全件を引き渡せる（09章）

09セキュリティ・データの扱い

観点方針
アクセス制御招待制ログイン。役割 × 店舗 × 区分の権限（06章）を画面とデータベースの両方で適用。退職・異動時は管理者が即時停止
通信・保管通信は暗号化（HTTPS）。データベース・ファイルは事業者側で暗号化保管。日次バックアップ
記録ログイン、閲覧（守秘対象項目）、変更を監査ログとして保存。項目単位の変更履歴で「誰が・いつ・何から何へ」を追える
守秘対象の項目再編所見・判定理由・総評・ヒアリング原文は判定会議メンバーのみ閲覧（既定）。設定で変更可
写真お客様・従業員・車両ナンバーの写り込みは、社外資料へ出力するときにマスキングする運用（要領書 9章）。アプリはマスキング済み写真の差し替えを支援
データの所有入力されたデータ・写真・資料は貴社の資産。契約終了時は全件（データベース・ファイル・Excel 出力）を引き渡し、弊社側の複製は削除
データの所在国内リージョンの利用を想定（契約時に確認）。利用するクラウド事業者と契約名義は 12章で確認
障害時「止める・戻す・データを戻す」の手順書をリリース前に用意し、復旧目標を保守契約に明記

10保守・運用

アプリを納めて終わりではなく、調査期間中と、その後の年次更新まで含めて運用します。内容は3層に分け、それぞれ範囲を明確にします（費用はお見積りで）。

層 1サーバー管理

クラウド利用料の管理、監視、日次バックアップの確認、部品の更新（脆弱性対応）、障害時の一次対応と復旧

層 2アプリ保守

不具合修正、問い合わせ対応、マスタ改訂（v1.1 など）の適用支援、小規模な改修。月あたりの対応時間の上限を決め、超過分は別途

層 3入力業務支援

受領資料からの転記代行、写真整理、年次更新時の入力代行と督促、判定会議資料の作成補助。調査期間中と年次更新時にスポットで

年次・定期更新の運用（案）

  1. 年度の切り替え時に、前年の回答・スコアを引き継いだ新しい調査年度を作成する（A-12）
  2. 「更新が必要な項目」（修繕履歴・設備の年式・実績データ・商圏指標など）を対象に、担当者へ更新依頼を出す。変化しない項目（竣工年月・構造など）は再入力しない
  3. 更新後にスコアリングを見直し、前年との差分（点数の変化・判定の変化）を全店ダッシュボードで確認する
  4. 投資計画の進捗（実施フェーズ・概算投資額）は年度をまたいで追跡し、実施済みの店舗はその旨を記録する

更新の頻度（年1回か、修繕のたびか）と対象項目は 12章で確認します。

11導入ステップ

要領書の標準スケジュール（パイロット2店舗 → 全店ウェーブ → 判定会議）に、アプリの構築を重ねます。パイロットまでに最初の版を使える状態にすることが要点です。期間は体制と要件の確定後にお見積りと合わせて提示します。

  1. 要件の確定

    本資料の 12章 を打ち合わせで確定。項目マスタ（雛形 v1.0）の取り込み、権限の割当方針、出力様式、認証方式の承認

  2. 第1版の構築（縦に1本通す）

    ログイン → 店舗カルテ → 調査入力（12区分）→ 写真添付 → スコアリング → 全店ダッシュボード → Excel 出力を、まず一通り動く形で。ここで最も難しい部分（権限・出力・現地入力）を先に検証

  3. パイロット2店舗をアプリで実施

    要領書の第3〜5週にあたる。現地入力・写真・ヒアリング・スコアリングまで通し、使い勝手と雛形の改訂点を集める

  4. v1.1 反映

    雛形・要領書の v1.1 改訂と同時に、マスタとアプリを改訂。全店展開に必要な機能（レビュー・年度・マスタ管理の画面）を揃える

  5. 全店展開

    現地調査ウェーブ（週2〜3店舗）と商圏分析の一括実施に並走。週次定例は全店ダッシュボードで

  6. スコアリング・判定会議

    相対評価の基準確定、ブロック別判定会議資料の出力、PM最終判定の記録。サマリー確定と中長期実行計画への引き渡し

  7. 年次更新モードへ

    調査完了後は年度管理と保守・入力支援の体制に移行

A-3 用語

  • カルテ — 店舗 × 調査年度の記録一式（168項目の回答・スコア・添付・承認状態）
  • マスタ — 調査区分・項目・選択肢・評価軸・評価基準・重み・判定ロジックの定義。版番号で管理
  • 耐震フラグ — 1-2 の入力から自動判定する「最優先」表示。旧耐震かつ未診断／未補強など
  • 自動判定 — A（建物・安全性）と C（商圏・将来性）の平均点による S／A／B／C の参考判定。最終判定は PM
